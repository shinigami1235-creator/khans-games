# Khan's Games — project handoff

Upload this file **and `index.html`** to Claude to carry on. `index.html` contains
every line of game code; this file explains the decisions behind it so you don't
have to re-derive them or accidentally undo them.

---

## What this is

Three browser games in one self-contained HTML file. No build step, no
dependencies, no network calls. Written in plain ES5-style JavaScript with
`<canvas>` 2D rendering and Web Audio for sound.

| Game | Players | Core idea |
|---|---|---|
| Tank | 1–2 | Tank drives forward on its own. Hold ◀ ▶ to steer, FIRE to shoot. |
| Brick Duel | 1–2 | Paddles on left and right walls, brick field in the middle. |
| Dino Rush | 1 | Endless runner, 16 hazard types, coins, double jump. |

**Important:** the three standalone files are the source of truth. `index.html`
embeds copies of them. Editing a game means editing the standalone file and then
rebuilding the hub — never hand-edit the base64 inside `index.html`.

## Rebuilding the hub

The hub is generated by a Node script that base64-encodes each standalone game
and injects it into a template. If you no longer have the script, it does this:

1. Read each game file, `Buffer.from(html).toString('base64')`.
2. Write those strings into a `BLOBS` object in the hub's script.
3. On card click, decode with `atob` → `TextDecoder` and set `iframe.srcdoc`.

Games run inside an iframe **on purpose**. Each one declares its own `ctx`,
`reset`, `draw`, `update` and `keydown` handlers — dropping them into one page
together would collide on every one of those names. The iframe gives each game a
clean global scope with zero refactoring. Don't "simplify" this by merging them.

After any change, verify the embedded copy still decodes byte-identical to its
source file.

## Design decisions worth not undoing

These were arrived at through playtesting. Each one replaced something worse.

**Tank**
- Shells bounce twice off walls but **cannot kill the tank that fired them**.
  Self-kills were tried and felt punishing rather than tense.
- The arena is randomly generated each round, but always in **180°-rotated
  pairs**, so neither player gets a better spawn. Verified over 400 generations.
- Wall blocks are `#8A8474` on a `#241F16` floor. An earlier build used
  `#3B372C` on `#22201A` — a contrast ratio of 1.37, which made the arena look
  completely empty on a phone in daylight. Don't darken them again.
- Bushes conceal (tank drops to 42% opacity) but shells pass through. They are
  cover for the eye, not for the body.
- Crates drop every 20s and **expire after 10s**, so they're a race, not a
  pickup. Six powers, 15s each: shield, rapid fire, scatter, heavy shell,
  overdrive, aim line.

**Brick Duel**
- Two open lanes are guaranteed through the brick field. Random placement alone
  sometimes produced an impassable wall.
- Bricks respawn in a **new random position** 5–9s after being destroyed, so the
  field keeps reshaping mid-match.
- Scoring is split: goals decide the match, points (goal 100 / brick 10 /
  return 1) reward working the field. You can lose on goals and win on points.

**Dino Rush**
- The second jump is deliberately weaker (−360 vs −430) so it extends the arc
  rather than doubling it.
- The high bird is only dangerous if you jump — it punishes panic.
- Falling blocks solve for a **fixed landing point on screen**; as the game
  speeds up the block falls harder to compensate. Without this it drifts back
  into the player's face at high speed.
- Hazards unlock by score (80 → 1100) so the vocabulary grows instead of the
  game only getting faster.

**Everywhere**
- Every game has a `layout()` function that measures the space actually left
  after the HUD and controls, then sizes the canvas to fit. An earlier build
  sized the canvas from width alone; on a phone the page came out ~750px tall,
  and because the body is a centred flex column with `overflow:hidden`, the
  controls were clipped off **both** ends at once. Keep `layout()`.
- Touch uses raw **touch events**, not pointer events. `setPointerCapture` on
  the canvas swallowed the second finger, so one player's controls went dead in
  two-player games. Don't switch back to pointer events.
- Music and SFX are generated with oscillators — no audio files. Each game has a
  32-step pattern (bass, lead, kick, hat). Music ducks to ~⅓ volume on big
  moments then fades back.

## Style preferences

Terse UI text. State a thing once and stop. No reassuring padding — not
"Your score has been saved successfully!", just the number.

## Known gaps / next ideas

- No high-score persistence except Dino Rush (localStorage).
- Tank's AI chases crates and shoots on a clear line; it doesn't lead its shots.
- Brick Duel's AI predicts the bounce but has a deliberate reaction delay and a
  random aim error — that's the difficulty dial if you want to tune it.
- No landscape-specific layout; everything scales but nothing re-arranges.
